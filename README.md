# Система мониторинга новостей из Telegram

Ниже — согласованное техническое описание и практическая структура проекта для сервера, который собирает новости из Telegram‑каналов, позволяет операторам фильтровать и обрабатывать ленту, а также управляется через Telegram‑бота.

## Ключевая цель

Автоматически собирать новости из Telegram‑каналов, помогать операторам быстро находить важные события и минимизировать пропуски, сохраняя устойчивость к сбоям сети и перегрузкам.

## Выбранный стек

- **Python 3.11+** — асинхронный, зрелые библиотеки под Telegram и веб‑интерфейсы.
- **Telethon (MTProto)** — чтение каналов «как пользователь»; устойчивые переподключения.
- **python-telegram-bot (async)** — управление и статус через Telegram‑бота.
- **FastAPI** — REST + WebSocket для «живой ленты».
- **PostgreSQL** — хранение сообщений, источников, тегов, отметок и аудита.
- **Redis + RQ/Celery** — фоновые задачи (ингест, обработка, алерты).
- **Web‑панель** (React/Vue) — интерфейс операторов в браузере локальной сети.

## Архитектура (4 независимых контура)

### 1) Collector (Telegram Ingest)

- Подключается к Telegram через Telethon.
- Подписывается на список каналов.
- Пишет новые сообщения в БД и/или очередь.
- При разрыве сети уходит в backoff‑режим, при восстановлении — продолжает.

### 2) Processor (Нормализация и правила)

- Чистит текст, определяет язык, нормализует слова/фразы.
- Применяет правила фильтрации, дедупликации, ранжирования.
- Формирует срочные алерты и «важные» события.

### 3) API + UI (Панель операторов)

- Лента с поиском, фильтрами и быстрыми действиями.
- Управление источниками и правилами прямо из интерфейса.
- WebSocket‑уведомления для «горячих» событий.

### 4) Control Bot (Telegram‑управление и статус)

- Команды управления (старт/стоп, добавление каналов/слов, срочный поиск).
- Отправка текущего состояния и алертов в указанный чат.
- Белый список Telegram ID + журнал действий.

## Функциональность панели операторов

### Лента сообщений

- Поток новых постов с подсветкой ключевых слов.
- Метки «важно/в работу/неинтересно».
- Быстрый переход к исходному сообщению в Telegram.

### Фильтрация и выбор

- Фильтры по источнику, ключевым словам, времени, языку, категории.
- Сохранённые наборы фильтров для смен/команд.

### Управление источниками

- Добавление/удаление каналов.
- Группы каналов (папки).
- Приоритеты каналов (для ранжирования).

### Управление словами и правилами

- Ключевые слова, фразы, синонимы.
- Минус‑слова (для снижения шума).
- Логические наборы (AND/OR) и ограниченные регулярки.

### Срочный поиск по одному слову

- **По истории:** мгновенный поиск по базе (PostgreSQL FTS).
- **По потоку:** временный «триггер» (30–180 минут), мгновенный алерт.

### Выделение «желательных новостей»

- Приоритет P1/P2/P3.
- Причина, ответственный, дедлайн, комментарий.

## Устойчивость и автозапуск

- **Linux:** systemd unit с `Restart=always` и зависимостью от `network-online.target`.
- **Windows:** служба + Task Scheduler (перезапуск при сбоях).
- Collector распознаёт пропадание сети, входит в backoff, затем восстанавливается.
- `/health` endpoint и watchdog‑перезапуск для зависших процессов.

## Управление через Telegram

Пример набора команд:

- `/status` — состояние каналов, очередь, ошибки.
- `/pause` и `/resume` — остановить/возобновить сбор.
- `/add_channel @name` — добавить канал.
- `/disable_channel @name` — выключить канал.
- `/add_keyword слово` — добавить слово.
- `/del_keyword слово` — удалить слово.
- `/urgent слово 90m` — срочный триггер на 90 минут.
- `/last_important 20` — последние 20 отмеченных «важно».

## Хранение данных (минимальный набор таблиц)

- **channels**: id, title, username, enabled, priority
- **messages**: id, channel_id, text, date, media, hash
- **keywords**: id, term, type (word/phrase/regex), enabled
- **flags**: id, message_id, level (P1/P2/P3), reason, assignee, deadline
- **audit_log**: id, actor, action, payload, created_at

## Расширение с LLM (опционально)

Если нужен авто‑анализ (суммаризация/категоризация), его следует сделать опциональным этапом:

- **Qwen2.5‑7B‑Instruct** или **Llama 3.1 8B Instruct**.
- Развёртывание локально через vLLM/Ollama.
- Возможность отключить LLM без влияния на сбор и поиск.
